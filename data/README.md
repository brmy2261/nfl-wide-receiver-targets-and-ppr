# Data source, collection, and dictionary

## Source and reuse

Source: [nflverse 2024 weekly player statistics](https://github.com/nflverse/nflverse-data/releases/download/player_stats/player_stats_2024.csv), documented in the [upstream player-statistics dictionary](https://nflreadr.nflverse.com/articles/dictionary_player_stats.html).

Data attribution: nflverse contributors, licensed under [Creative Commons Attribution 4.0](https://creativecommons.org/licenses/by/4.0/) ([source license](https://github.com/nflverse/nflverse-data/blob/main/LICENSE.md)). The shared samples are modified extracts: filtered to 2024 regular-season wide receivers, reduced to relevant fields, sorted, and sampled. The paired sample also joins consecutive weeks and adds a target group. The data are provided without warranties; see the source license.

Collection ran on **November 8, 2026 at 23:01:52 UTC (4:01:52 p.m. MST)**. The download returned HTTP 200, with **5,597 rows, 53 columns, and 1,674,023 bytes**. [collection_metadata.json](collection_metadata.json) records the exact source, timestamp, identifying User-Agent, status, byte count, and SHA-256 checksum.

The collector downloads GitHub's [robots.txt](https://github.com/robots.txt) and saves it locally for review. The rules reviewed on the collection date did not prohibit this specific release-asset path. GitHub's [Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service) and [Acceptable Use Policies](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies) govern access. This project downloads a published data asset rather than crawling pages or collecting GitHub users' information. It relies on the source's reuse license, not a blanket educational fair-use claim.

Requests identify `BrendanMyers-ClassResearch/1.0` and link this project. The code waits at least two seconds between requests, including redirects, uses timeouts, caches the raw file, and stops on HTTP 403/429 with any Retry-After instruction displayed. It does not repeatedly retry denied requests. Review current access rules before a fresh collection; the saved robots file is a record, not an automated permission check.

## Cleaning and record counts

[scripts/clean.py](../scripts/clean.py) verifies the raw-file checksum, trims text fields, selects WR / REG / 2024 records, retains seven fields, converts numeric columns, and checks player IDs, finite values, integer weeks 1–18, and nonnegative integer targets. Negative fantasy points are allowed. Missing values are not replaced by zeros. Exact duplicate rows would be removed; conflicting duplicate player-week keys stop the run for review.

| Stage | Records |
| --- | ---: |
| Raw player statistics | 5,597 |
| Excluded other positions or season types | 3,465 |
| Selected regular-season WR player-weeks | 2,132 |
| Invalid or missing rows removed | 0 |
| Exact duplicate rows removed | 0 |
| Clean player-weeks, covering 227 receivers | 2,132 |
| Eligible predictor rows, weeks 1–17 | 2,012 |
| Eligible rows without a next-calendar-week record | 452 |
| Matched consecutive-week pairs | 1,560 |

The pair table joins on player ID, season, season type, and the next NFL week number. A week 3 record is never paired with week 5 merely because week 4 is absent. Week 18 cannot be a predictor because the study stops at week 18. Missing next-week records may reflect byes, injuries, or other absence; these data alone do not establish the cause. See [cleaning_summary.json](cleaning_summary.json) and the executed [notebook](../analysis.ipynb) for actual output.

## Files and privacy

- [wr_weekly_sample.csv](wr_weekly_sample.csv): 50 rows randomly selected with seed 42 from the full clean player-week table, then sorted by player/week.
- [wr_pairs_sample.csv](wr_pairs_sample.csv): 50 rows selected independently with the same seed from the full matched table, then sorted. These are examples for inspection, not the data to use for final correlations.
- `raw/`: local-only unmodified CSV and robots snapshot, excluded through `.gitignore`.
- `processed/`: local-only full weekly and paired CSVs, regenerated by the cleaning script.

The raw file contains athlete names and headshot URLs as well as many fields unrelated to this question. I keep it out of Git to avoid redistributing unnecessary identifying fields and duplicating a downloadable source. At about 1.7 MB, its size is not a GitHub limit, and the CC BY license permits attributed reuse; this is a data-minimization choice. Full processed files are also omitted to keep the public portfolio focused on a small reproducible sample. Player IDs are retained for matching and can be linked to public professional-athlete identities, so the samples are **not anonymous**. Names, photos, photo URLs, fantasy-manager accounts, and private league information are not included in the cleaned tables.

## Data dictionary

One row in `wr_weekly_sample.csv` is one receiver's recorded NFL week. The unique key is `(player_id, season, season_type, week)`. One row in `wr_pairs_sample.csv` is that receiver's predictor week plus an observed next-week outcome. Neither table has missing values in this run.

| Field | Type | Meaning / units |
| --- | --- | --- |
| `player_id` | string | Source GSIS player identifier, preserved with its leading zeros and hyphen; used to match a receiver across weeks. |
| `season` | integer | NFL season year; always 2024 here. |
| `season_type` | string | Source season classification; always `REG` (regular season). |
| `week` | integer | NFL week of the predictor/current observation, 1–18 in the weekly table and 1–17 in the pair table. |
| `position` | string | Source player position; always `WR` (wide receiver). |
| `targets` | integer | Number of passes directed to the receiver in that week; zero is a valid count. |
| `fantasy_points_ppr` | decimal | Source full-PPR fantasy score for the current week, in points; includes one point per reception and other scoring components, not just receiving points. Used as supplied by nflverse. |
| `next_week_ppr` | decimal, pairs only | The same player's source `fantasy_points_ppr` for exactly `week + 1`. |
| `next_week` | integer, pairs only | NFL week supplying the outcome; always `week + 1`, from 2–18. |
| `target_group` | string, pairs only | Derived from current-week targets: `0-3`, `4-7`, or `8+`. |
